# Network behavior

Dex has **no analytics or telemetry collector**. It does make the following service requests. This describes Dex's own code; Claude Code, npm, browsers and tasks executed by agents have their own network behavior and privacy terms.

| Feature | Destination and data | When / behavior without setup | Source |
| --- | --- | --- | --- |
| Model news | `api.anthropic.com/v1/models?limit=1000`; GLM `api.z.ai/api/anthropic/v1/models`; Muse `api.meta.ai/v1/models`. Authenticated catalogue GETs with provider credentials. | Due check about 3 seconds after UI mount; successful checks are limited to once per provider per 24 hours. Missing credentials or failed requests skip that provider. | [UI](../src/team/ModelNews.tsx), [catalogue requests](../crates/dex-core/src/model_news.rs), [provider bases](../crates/dex-core/src/providers.rs) |
| Claude quota | `api.anthropic.com/api/oauth/usage`, with the locally stored Claude OAuth token. Retrieves account-wide usage/reset windows. | Quota monitoring polls every 60–600 seconds with backoff. Missing/expired credentials or failures leave quota unknown; stale data does not trigger proactive switching. | [quota](../crates/dex-core/src/quota.rs), [Core lifecycle](../crates/dex-core/src/lib.rs) |
| Playwright MCP | npm registry/package download via `npx -y @playwright/mcp@0.0.79`; subsequent browser traffic goes to task-selected sites. | Browser-enabled roles only; a cached pinned package can avoid installation. Browser sessions are headless and isolated; unavailable browser/package access breaks browser tools. | [browser launcher](../crates/dex-core/src/browser.rs), [agent wiring](../crates/dex-core/src/pty.rs) |
| GPU broker | User-configured primary/fallback broker URLs: model/recipe/status requests, approved job submissions with inputs, output downloads, and explicit admin operations. | No default host. Startup refresh requires a stored token; opening GPU settings can request status for configured hosts. Submissions require a grant and budget. Unconfigured/unreachable broker does not prevent normal local work. | [GPU implementation](../crates/dex-core/src/gpu.rs) |
| Remote dexd / tailnet | User-paired `ws`/`wss` hosts, carrying RPC requests/events and terminal/job data. Tailnet exposes a local dexd listener via the installed Tailscale network. | Remote registry starts empty; pairing is explicit. Tailnet is disabled by default and requires Tailscale. Tailscale's own control-plane traffic is governed by its configuration. | [hosts](../src/api/hosts.ts), [transport](../src/api/transport.ts), [tailnet](../crates/dexd/src/tailnet.rs) |
| Local LLM / LiteLLM | User-configured server URL: `/model/info` (fallback `/v1/models`) and `/health/readiness` GETs with the stored Bearer key; model add/remove sends `/model/new` and `/model/delete` POSTs with the model settings. | No default host. Requests start when the user opens the team/member form or edits local models. Unconfigured/unreachable server only hides local models. | [providers](../crates/dex-core/src/providers.rs), [team bar](../src/team/TeamBar.tsx) |
| Usage strip quotas | GLM `api.z.ai/api/monitor/usage/quota/limit` GET with the stored GLM key; Muse `api.meta.ai/muse-code/key` POST with the Muse CLI's OAuth login (`~/.config/muse/auth.json`), the same key-mint call the CLI makes at start. Only 5-hour/weekly window percentages and reset times are read; the minted key is discarded. Claude reuses the quota measurement above. | Same 60–600 second tiered polling with backoff as Claude quota. Missing credentials or failures show "--" for that provider. | [usage](../crates/dex-core/src/usage.rs) |

Development uses local Vite and dexd connections. Dependency installation and optional deployment/APK scripts also contact package registries or your configured SSH hosts when you run them ([package scripts](../package.json), [deployment guide](deploy.md), [APK script](../scripts/release-apk.mjs)).

## Local diagnostics

Core writes rotating diagnostics under its data directory's `logs/`: `dex-<UTCday>-<slot>.jsonl`, up to four 2 MiB files per day with seven-day retention. Its structured logger filters content to diagnostic metadata and redacts untrusted messages. The desktop also keeps local dexd startup/stderr logs; those can contain local paths and should be reviewed before sharing. There is no automatic diagnostic upload ([logger](../crates/dex-core/src/diagnostics.rs), [daemon initialization](../crates/dexd/src/main.rs), [startup logs](../src-tauri/src/core_proc.rs)).

These diagnostic limits do not cover CLI transcripts, browser output, project results or other application data. Agent tasks may send project content to model providers and external tools. Read the [security policy](../SECURITY.md) and [README](../README.md#security) before granting access.
